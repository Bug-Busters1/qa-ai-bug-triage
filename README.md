## 📋 3. تفاصيل متطلبات الوظائف (Functional Requirements - FRs)

### أ) وحدة إدارة المستخدمين والمصادقة (User Management & Authentication)
- **`FR-AUTH-01` (التسجيل والدخول):** يجب أن يوفر النظام واجهة لتسجيل حساب جديد وتسجيل الدخول بأمان للمستخدمين.
- **`FR-AUTH-02` (التحكم بالصلاحيات - RBAC):** يجب أن يطبق النظام صلاحيات الوصول بناءً على دور المستخدم لتقييد أو السماح بعرض الصفحات والوظائف.
- **`FR-AUTH-03` (إدارة الملف الشخصي):** السماح للمستخدم بإدارة معلومات حسابه الأساسية وتحديثها.

### ب) وحدة الإبلاغ عن الأخطاء وإدارتها (Bug Reporting & Management)
- **`FR-BUG-01` (إنشاء تقرير خطأ):** السماح للمستخدم بإنشاء Bug Report يتضمن العنوان، الوصف، خطوات إعادة الإنتاج، النتيجة المتوقعة، النتيجة الفعلية، وتفاصيل بيئة التشغيل.
- **`FR-BUG-02` (تتبع وتحديث الحالة):** تتبع حالة الباغ وإدارتها (`Open`, `Resolved`, `Closed`) وتحديث معلومات الإسناد والتكليف.
- **`FR-BUG-03` (البحث والفلترة):** توفير أدوات بحث متقدمة وفلاتر للبحث بين تقارير الأخطاء بسرعة ودقة.

### ج) وحدة الفرز الذكي المدعومة بالذكاء الاصطناعي (AI-Powered Bug Triage)
- **`FR-AI-01` (تحليل الوصف):** يقوم مكون الذكاء الاصطناعي بقراءة وتحليل وصف تقرير الخطأ المدخل تلقائياً.
- **`FR-AI-02` (اقتراح الخطورة والأولوية):** يولد النظام مقترحات دقيقة لمستوى الخطورة والأولوية للباغ.
- **`FR-AI-03` (التصنيف والفئة):** تصنيف الأخطاء تلقائياً إلى الفئات المحددة مسبقاً.
- **`FR-AI-04` (كشف الباجات المكررة):** فحص قاعدة البيانات ومقارنة الباغ الحالي بالتقارير السابقة لتحديد التقارير المكررة المحتملة.
- **`FR-AI-05` (التلخيص الآلي):** توليد ملخص قصير ومركز للعيوب المبلغ عنها.
- **`FR-AI-06` (توصية المطور المسؤول):** اقتراح الفريق أو المطور المناسب للتعامل مع الباغ استناداً إلى قواعد الإسناد وبيانات الفريق المتاحة.

### د) وحدة إدارة حالات الاختبار (Test Case Management)
- **`FR-TC-01` (إنشاء وتحديث الحالات):** السماح لمهندسي الجودة بإنشاء وتعديل حالات الاختبار مع تحديد خطوات الاختبار والنتائج المتوقعة.
- **`FR-TC-02` (تسجيل نتائج التنفيذ):** تسجيل نتائج تنفيذ الاختبارات (`Pass` / `Fail` / `Blocked`).
- **`FR-TC-03` (الربط بالعيوب):** ربط حالات الاختبار بتقارير الأخطاء المرتبطة بها لسهولة التتبع.

### هـ) لوحة التحكم والتقارير (Dashboard & Reporting)
- **`FR-DASH-01` (الإحصائيات العامة):** عرض إجمالي عدد الأخطاء المبلغ عنها في واجهة مركزية.
- **`FR-DASH-02` (حالة العيوب):** عرض عدد الأخطاء المفتوحة، التي تم حلها، والمغلقة.
- **`FR-DASH-03` (التوزيع البصري):** تقديم رسوم بيانية توضح توزيع الأخطاء بناءً على درجة الخطورة والحالة.
- **`FR-DASH-04` (مؤشرات الأداء):** عرض مؤشرات أداء الجودة المختارة وتتبع تقدم نتائج الاختبار.

### و) المراجعة البشرية والتغذية الراجعة (Human Review & Feedback)
- **`FR-REV-01` (قبول أو تعديل مقترحات AI):** السماح للمستخدم المصرح له بقبول أو تعديل توصيات الذكاء الاصطناعي.
- **`FR-REV-02` (اعتماد التصنيف النهائي):** حفظ وتسجيل التقييم والتصنيف النهائي المعتمد بشرياً في النظام.
- **`FR-REV-03` (جمع التغذية الراجعة):** جمع تفاعلات المستخدمين لتقييم مدى فائدة ونجاح اقتراحات الذكاء الاصطناعي.

## 🛠️ التقنيات المقترحة (Tech Stack)

| الطبقة (Layer) | التقنيات المستخدمة (Technologies) |
| :--- | :--- |
| **Frontend** | React / Next.js, TypeScript, Tailwind CSS |
| **Backend** | Node.js (NestJS / Express) أو Python (FastAPI) |
| **Database** | PostgreSQL + Redis (للتخزين المؤقت وتحسين الأداء) |
| **AI Layer** | OpenAI / Gemini / Local LLMs + Vector Embeddings للكشف عن المكررات |
| **Auth** | JWT + Role-Based Access Control (RBAC) |
| **Charts** | Recharts / Chart.js |
| **Deployment** | Docker, Vercel / Railway / AWS |
